# WB Price Tracker

Telegram-бот, который следит за ценами на Wildberries **вместо меня**. Отправляешь ему артикул — он запоминает товар, раз в сутки проверяет цену и остатки, и пишет в личку, если цена упала или товар заканчивается.

Начиналось как учебное задание («трекер цен с пуш-уведомлением раз в сутки»), а закончилось мини-войной с антиботом Wildberries. Подробности ниже, там самое интересное.

## Команды

| Команда | Что делает |
|---|---|
| `/track 12345678` | начать отслеживать товар по артикулу |
| `/untrack 12345678` | перестать |
| `/list` | список отслеживаемых товаров |
| `/history 12345678` | история цен из SQLite |
| `/stats` | сколько товаров в базе, размер кэша, время до следующей проверки |
| `/diag` | диагностика: реальный запрос к API WB (для отладки антибота) |
| `/cleanup` | вычистить старую историю цен (хранится 30 дней) |

## Почему в проекте curl_cffi и «демо-режим»

Публичный API карточек Wildberries (`card.wb.ru`) — недокументированный и закрыт антиботом. С обычного домашнего IP он отвечает **403 или пустым массивом**. Я сначала написал всё на `httpx` — не работало. Переписал на `curl_cffi` с отпечатком браузера Chrome — заработало, но не всегда: WB ещё и по IP режет. Поэтому:

- по умолчанию HTTP-клиент — `curl_cffi` (имитация Chrome);
- есть переменная `WB_PROXY` для прокси с «чистым» IP;
- есть команда `/diag`, чтобы понять, что именно отдал API;
- и честный **демо-режим** (`WB_DEMO_MODE=1`): бот ходит в сеть только для проверки токена, а цены берёт выдуманные. Весь функционал работает без единого запроса к WB.

Честное признание: для реальной эксплуатации правильнее официальный Seller API WB. Но для учебного проекта и показа того, как я умею обходить такие ограничения, это даже полезнее.

## Запуск

```bash
python -m venv .venv
pip install -r requirements.txt
export WB_BOT_TOKEN=123456:ABC...   # токен от @BotFather
export WB_DEMO_MODE=1               # 0 — реальный API WB
python bot.py
```

На Windows проще: `run_bot1.cmd` сам возьмёт `TG_TOKEN` из корневого `.env`, включит демо-режим и запустит бота из `.venv`.

Все настройки — в `.env.example`: интервал проверки (по ТЗ раз в сутки = 1440 минут), кулдаун уведомлений (6 часов, чтобы не спамить), сколько дней хранить историю, кто админ для `/cleanup`.

## Из чего состоит

```
bot.py          — команды, планировщик проверок, рассылка уведомлений
wb_api.py       — клиент карточек WB (curl_cffi/httpx), поддержка прокси
alerts.py       — решение «уведомлять или нет»: кулдаун, порог снижения цены
db.py           — aiosqlite: товары, история цен, индексы, очистка
middlewares.py  — троттлинг (защита от спама) и логирование
config.py       — переменные окружения с дефолтами
utils.py        — TTL-кэш карточек и retry с джиттером на чистом stdlib
tests/          — 9 тестов (парсинг ответа WB, кулдаун, БД, извлечение артикула)
```

## На чём я споткнулся

1. **403 от WB на обычных запросах.** Отпечаток TLS и HTTP/2 рулит. `curl_cffi` с имитацией Chrome решил.
2. **Эмодзи роняли бота в Windows-консоли** — `UnicodeEncodeError` (кодировка cp1251). Лечится `PYTHONIOENCODING=utf-8`, это прописано в `run_bot1.cmd`.
3. **База росла бесконечно** — каждое отслеживание плодило записи. Добавил индекс на `(articul, checked_at)`, плановую очистку старше N дней и `/cleanup`.
